## B. Root Causes Found

1. **Duplicate Example Cards Origin:**
   - **JSON / JS Source Data (Primary):** Generation scripts in content_builder/ appended identical exemplar blocks up to 15 times per day to meet array size targets (e.g. 100 exemplars per day).
   - **Loader Function (Mitigation):** curriculumRegistry.ts contains a runtime seenExamples = new Set() filter inside normalizeDayLesson(). However, any view or builder directly accessing raw JSON or bypass methods bypasses this deduplication and renders identical duplicate cards on screen.

2. **Missing Scenarios / Dialogue Turns Origin:**
   - **JSON / JS Source Data:** Days 11–20 and Days 31–40 in content_builder/ are missing the dialogues / dialogue object inside the use block (0 scenarios and 0 turns present in raw data).
   - **Fallback Logic (Synthetic Generation):** curriculumRegistry.ts (lines 354–368) contains a fallback that synthesizes a fake 2-turn dialogue using examples[0] and examples[1] when rawTurns.length === 0.

3. **Practice Integrity & Missing Answer Keys Origin:**
   - **Source Data:**
     - Days 41–50 practice arrays are missing correctAnswer or targetText fields on all 95 exercise items per day.
     - Days 24–29 are missing correctAnswer keys on 20 translation items per day.
     - Days 2–10 contain high prompt duplication (up to 60 repeated prompts per day) due to looped exercise generation in content_builder/.

4. **JSON File Syntax / Encoding Issues:**
   - The root JSON content packs (DAYS_01_10_CONTENT.json through DAYS_51_60_CONTENT.json) contain unescaped control characters (newlines/tabs) and binary artifacts inside Hindi text strings, causing standard JSON.parse to fail unless sanitized or loaded via JavaScript modules.
